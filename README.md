# TALA Study Planner

دفتر دراسة ومهام شخصي بواجهة عربية RTL وهوية بنفسجية وذهبية.

الموقع: https://aboodsharef-maker.github.io/models-3d/

المستودع نفسه محفوظ باسم models-3d. لم يتم إنشاء مستودع أو إعداد Pages جديد.

## ما يقدمه التطبيق

- مواد قابلة للإضافة والتعديل والحذف والترتيب، مع ألوان وأيقونات مخصصة.
- أقسام متداخلة حتى ثمانية مستويات، ومهام مباشرة أو داخل الأقسام.
- تعديل المهام ونقلها وترتيبها، إكمالها وإلغاء الإكمال، ونسب إنجاز تراكمية للأقسام والمواد.
- جدول أيام وتقويم، ومواعيد امتحانات بعد تنازلي.
- دفتر ملاحظات وملاحظات مهام غنية التنسيق باستخدام Tiptap: الخطوط والأحجام والألوان والتظليل والقوائم وعلامات الصح واتجاه الكتابة.
- إنجازات محسوبة من البيانات الفعلية، وثلاث لوحات ألوان وخطوط عربية محلية.
- تصدير واستيراد JSON مع فحص البنية والروابط والتواريخ والتنسيقات، وتنزيل نسخة من الدفتر الحالي قبل استبداله.

تُجهز ست مواد أولية بأسماء قابلة للتعديل، دون مهام أو امتحانات أو إنجازات وهمية.

## البيانات والخصوصية

الحفظ التلقائي في IndexedDB تحت اسم tala-study-planner مستمر. عند تهيئة VITE_SYNC_API_URL تتزامن النسخة مع Cloudflare Worker وقاعدة D1 المستقلة tala-study-sync. المساحة عامة ومشتركة عمدًا: لا حسابات أو شاشة دخول، وكل زائر يستطيع القراءة والتعديل. GitHub Pages يستضيف الواجهة فقط، ولا يحتفظ بالدفاتر في مستودع Git.

استخدمي نفس المتصفح للعودة إلى الدفتر. مسح بيانات الموقع أو انتهاء جلسة تصفح خاص قد يفقد البيانات؛ صدّري نسخة JSON بانتظام، واستورديها لنقلها إلى جهاز آخر. يوضح التطبيق حالة الحفظ ويعرض خطأً قابلًا لإعادة المحاولة إذا تعذّر التخزين. لا يعمل دفتر متزامن على أكثر من تبويب؛ تُعرض رسالة عند اكتشاف تعديلات في تبويب آخر.

بنية البيانات تحمل schemaVersion ومعرّفات UUID وdeviceId وrevision وطوابع إنشاء وتحديث. المزامنة تستخدم المعرفات، وقاعدة سابقة مشتركة، وسجل تغييرات محليًا؛ لا تختار النسخة الأحدث زمنيًا على حساب الأخرى.

## التطوير والتحقق

```sh
npm ci
npm test
npm run build
npm run dev
```

افتحي /models-3d/ من عنوان التطوير. يستخدم التنقل hashes حتى تعمل الروابط وإعادة التحميل على GitHub Pages. يتطلب البناء Node.js 24 كما في workflow.

التنفيذ: src/data.ts للحسابات وفحص النسخ، src/storage.ts للحفظ الذري وتسلسل الكتابات، src/components/ للمكونات والمحرر والنوافذ، src/pages/ للشاشات، public/assets/ للهوية المستقلة الشفافة. الخطوط من حزم Fontsource محفوظة ضمن البناء، ولا يعتمد التطبيق على CDN أو خطوط عن بعد.

## النشر

نفس ملف .github/workflows/pages.yml ونفس بيئة github-pages. عند الدفع إلى main: npm ci ثم npm test ثم npm run build، ورفع dist/ فقط. لا تُرفع ملفات الاختبارات أو المستندات المحلية أو ملفات المجسمات القديمة أو البيانات الشخصية إلى الموقع.

## نقطة رجوع المشروع السابق

وسم Git مشروح ومرفوع: backup/models-3d-before-tala-2026-10-31.

للفحص دون تعديل main:

```sh
git switch -c inspect-old-gallery backup/models-3d-before-tala-2026-10-31
```

لا تعيدي نشر الوسم بنفس workflow الجديد مباشرة؛ نسخة الوسم تحمل ملفات المعرض وطريقة نشره الأصلية كاملة. لاستعادة الموقع القديم راجعي تغييرات main أولًا ثم أنشئي عملية استعادة واضحة من الوسم، مع إبقاء أي تعديلات لاحقة محفوظة.

## الهوية والمراجع

استُخدمت الصور المرفقة كمرجع للون والمزاج البصري فقط. واجهة التطبيق مكونات فعلية، وليست صورة. الشعار والتاج والفراشة والوردة والهلال والنجوم ملفات SVG مستقلة بخلفيات شفافة؛ الخطوط Tajawal وCairo وAmiri من Fontsource وفق تراخيص الحزم.

## تطبيق أندرويد والتحديثات (1.1)

افتحي الرابط في Chrome على أندرويد واضغطي «تثبيت التطبيق». إذا لم تظهر النافذة، استخدمي قائمة Chrome ثم «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية ← تثبيت». هذا تطبيق ويب قابل للتثبيت PWA، وليس إصدار متجر Play أو APK. يفتح بأيقونته في نافذة مستقلة؛ الآيفون يستمر كموقع عادي ويمكن إضافته للشاشة الرئيسية.

تُخزن ملفات الواجهة والخطوط والمصحف للعمل دون اتصال بعد اكتمال التهيئة الأولى. كلمة «جاهز دون اتصال» داخل التطبيق تعني أن خدمة العمل دون اتصال أصبحت جاهزة. يلزم الإنترنت للتنزيل الأول ولتلقي الإصدارات الجديدة. مع المزامنة المفعلة، تُشارك بيانات الدفتر وسجل العبادة في مساحة Cloudflare العامة حسب طلب مالك المشروع.

كل npm run build يولد sw.js وversion.json مع بصمة للمحتوى. النسخة الجديدة تنتظر، ويظهر زر «تحديث الآن» عند جاهزيتها. التحديث لا يحذف IndexedDB، ويُمنع تطبيقه أثناء الحفظ أو فتح نافذة تعديل. يتم البحث عن تحديث عند فتح التطبيق/العودة إليه وعند الاتصال وكل 15 دقيقة أثناء فتحه. التحديثات تصل بعد دفع التغييرات إلى main ونجاح نشر GitHub Pages؛ لا حاجة لإعادة تثبيت التطبيق في كل مرة.

tools/generate-icons.mjs يولد PNG بمقاسات 180 و192 و512 وأيقونة maskable من SVG مستقل. ملفات PNG ملتزم بها في المستودع.

## الصلاة والقرآن

سجل يومي قابل للتعديل للصلوات الخمس، وخطط ختمة متعددة بمدة وعدد صفحات قابلين للتخصيص، وسجل ورد يومي من/إلى صفحة مع ملاحظة. تحسب الختمة الصفحات المختلفة فقط؛ إعادة قراءتها لا ترفع نسبة الختمة مرتين. توجد قراءة داخل التطبيق بترقيم 604 صفحة ونص عثماني، مع اختيار سورة وصفحة وحجم خط وإضافة الصفحة إلى الورد. لا توجد مواقيت أذان أو تنبيهات أو طلبات موقع.

النص العربي محفوظ دون تعديل من Al Quran Cloud / Islamic Network، إصدار quran-uthmani. المصدر والحقوق والروابط وبصمة الاستجابة الأصلية موضحة في public/quran/SOURCE.txt وبيانات JSON. جرى فحص وجود 114 سورة و6236 آية و604 صفحة. لا يُجلب النص من خدمة خارجية أثناء استخدام التطبيق؛ هو ملف ثابت ضمن الإصدار.

أصبح إصدار مستند البيانات 2، مع ترقية تلقائية لدفاتر الإصدار 1 ونسخه الاحتياطية دون حذف موادها أو ملاحظاتها. نسخة IndexedDB نفسها ما زالت 1 لأن مخزن البيانات لم يتغير. يشمل تصدير JSON بيانات الصلاة والختمة والورد أيضًا.

يمكن سحب الصفحة للأسفل من أعلاها ثم الإفلات عند ظهور «اتركي للتحديث». تفحص الحركة إصدار التطبيق وتطبقه إن كان جاهزًا، وإلا تعيد فتح الصفحة المحفوظة. لا تعمل الحركة أثناء الحفظ أو داخل نوافذ التعديل والمحرر؛ السحب الأفقي والقصير لا يفعّلانها.


## المزامنة المشتركة والترحيل (1.2)

- frontend: https://aboodsharef-maker.github.io/models-3d/ ، API: https://tala-study-sync.aboodsharef.workers.dev . لا توجد أسرار في الواجهة؛ عنوان API ومعرف D1 إعدادات عامة.
- قاعدة الإنتاج tala-study-sync منفصلة تمامًا عن tala-study-sync-staging وعن staffdailybook. الاختبارات الوهمية تستخدم workerd/SQLite محليًا، والمتصفحان التجريبيان يستخدمان staging فقط. لا تُضاف بيانات اختبار للإنتاج.
- لا تتغير وثيقة الدفتر (schemaVersion=2) أو نسخة IndexedDB (1) أو مفتاح personal. تُضاف مفاتيح sync-state وsync-journal وbackup:* داخل مخزن planner نفسه.
- أول اتصال: نسخة محلية أصلية ثابتة، ثم نسخة في D1 مع معرف ثابت، ثم إعادة قراءتها والتحقق من SHA-256. عند سحابة فارغة يُرفع الدفتر المحلي كما هو؛ لا تُنسخ السحابة الفارغة إلى الجهاز. المتصفح الجديد غير المعدّل لا يرفع المواد التجريبية إلى دفتر قائم.
- تُحفظ عملية رفع معلقة قبل إرسالها، مع mutationId ثابت وbaseVersion. يخضع النشر لمقارنة النسخة على الخادم ضمن D1 batch ذري، ثم تُقرأ المراجعة الثابتة وتُفحص بصمتها قبل إقرار السجل المحلي واعتماد الترحيل. انقطاع الرد بعد نجاح الكتابة يعيد العملية نفسها ولا ينشئ عناصر مكررة.
- تعديلات حقول مختلفة تُدمج، والنص المنسق وحدة ذرية حتى لا يتلف تنسيقه. تعديلان مختلفان للحقل نفسه أو حذف/تعديل متعارضان يوقفان الدفع ويحتفظان بنسختين للمراجعة. اختيار المستخدم صريح، ويتقادم إذا تغيرت البيانات أثناء المراجعة. حذف الأب مع إنشاء طفل متزامن لا يسقط الطفل بصمت.
- المعرف نفسه لا يتكرر؛ عناصر بأسماء متشابهة ومعرفات مختلفة تُحفظ كما هي، إذ قد تكون مواد مقصودة مستقلة. سجلات الصلاة اليومية تُدمج حسب اليوم والصلاة؛ الصفحات لا تُضاعف داخل الختمة.
- يحفظ الخادم مراجعات تاريخية كاملة وtombstones للحذف. جسم المراجعة يُجزأ إلى صفوف صغيرة تجنبًا لحدود حجم صف D1. لا يوجد مسار API لحذف التاريخ نهائيًا. من مؤشر السحابة: تنزيل نسخة ما قبل النقل، عرض آخر 30 مراجعة، تنزيل أي مراجعة، أو إضافة العناصر المفقودة من مراجعة سابقة مع الاحتفاظ بالعناصر الحالية.
- واجهة المستخدم تتغير فورًا وتُحفظ دون شبكة. مزامنة بعد نحو 1.5 ثانية من الحفظ، وعند عودة الشبكة أو ظهور التطبيق، وكل 15 ثانية وهو ظاهر. لا تُطبق بيانات واردة أثناء نافذة تعديل أو كتابة غير محفوظة. قفل مستقل ينسّق دورات السحابة بين التبويبات، ولا يحبس الحفظ المحلي أثناء طلبات الشبكة. معاملة IndexedDB تعيد دمج التعديلات التي وصلت أثناء النقل وتُقرّ الدفتر والمرجع والسجل معًا.
- API عام حسب الطلب، والتحقق من Origin/CORS وتحديد معدل الكتابة لا يمثلان مصادقة ولا يجعلان الدفتر خاصًا. لا تضعوا معلومات سرية في هذه المساحة العامة. يستخدم API استجابات no-store، ولا تلتقط خدمة PWA طلباته لأنها خارج أصل الواجهة.
- تجاوز الحصة أو قطع الاتصال أو فشل فحص البصمة يوقف الإقرار فقط: يبقى الدفتر المحلي ونسخة الترحيل والسجل، مع إعادة محاولة لاحقة.

### تشغيل الاختبار والنشر

npm test يتضمن اختبار عميلين مستقلين مع Worker وD1 فعليين تحت Miniflare، لا مجرد mock لقاعدة البيانات. npm run check:worker يفحص API. npm run build يبني الواجهة وخدمة العمل دون اتصال.

للواجهة المحلية حددي VITE_SYNC_API_URL إلى worker الاختبار في بيئة الأمر، ثم شغلي Vite على 5183 و5184 (أصلان مستقلان لـIndexedDB). يسمح Worker التجريبي بهذين الأصلين فقط. بدون المتغير تبقى الواجهة محلية. إعداد GitHub Actions يضع عنوان الإنتاج أثناء البناء؛ لا توجد .env تحتوي أسرارًا مطلوبة.

أوامر إدارة الخلفية، من جذر المستودع:

```sh
npx wrangler d1 migrations apply tala-study-sync-staging --config backend/wrangler.jsonc --remote
npx wrangler deploy --config backend/wrangler.jsonc
npx wrangler d1 migrations apply tala-study-sync --config backend/wrangler.production.jsonc --remote
npx wrangler deploy --config backend/wrangler.production.jsonc
```

تغيير READ_ONLY إلى true ونشر Worker يوقف الكتابة السحابية لحين معالجة مشكلة، دون مسح المحلي أو D1. لا تعيدي إنشاء قاعدة البيانات أو تنفيذ DROP/DELETE على الإنتاج. لإيقاف المزامنة بالواجهة أزيلي VITE_SYNC_API_URL من البناء؛ النسخ المحلية تظل قابلة للفتح والتصدير. لا يُدّعى أن جهاز أخت المستخدمة ترحّل فعليًا قبل فتحه الإصدار الجديد.

## شرائط الصلاة والختمة

نور اليوم تحت الهيدر يتحدث من 0 إلى 5 مع وجه تزداد ابتسامته، واحتفال عند إكمال الصلوات. أزرار الصلوات السريعة مرتبطة بنفس السجل. اليوم يتجدد عند منتصف الليل/عودة التطبيق. شريط الختمة يعرض صفحات الخطة النشطة، والإنجازات تعرض الأيام المكتملة وسلسلتها، وأيام القراءة ومعالم 25/50/75/100% لكل خطة. لا تُعرض ختمة مكتملة بسبب التقريب (603 من 604 = 99%). كل العدادات من البيانات الفعلية وتراعي تفضيل تقليل الحركة.

مراجع التنفيذ: [D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/)، [الاختبار بـworkerd](https://developers.cloudflare.com/workers/testing/miniflare/).
